# Настройка

**Problem Desk - общее рабочее пространство организации.** Он не воспроизводит права доступа Grafana Alerting на уровне папок. Данные оповещений, видимые сервисной учетной записи, через плагин доступны участникам организации. Администратор не должен включать приложение там, где это раскроет данные с ограниченным доступом.

Администратор настраивает приложение через `jsonData.grafanaUrl` и `jsonData.pollIntervalSeconds` (по умолчанию `30`), а в `secureJsonData.grafanaToken` задает токен сервисной учетной записи Grafana в пределах организации с правом чтения оповещений. Backend сверяет `/api/org` с доверенным ID организации плагина Grafana. Не помещайте токен в обычную JSON-конфигурацию и не публикуйте его в логах.

Backend хранит данные в SQLite отдельно от базы Grafana. По умолчанию `PROBLEMDESK_DATA_PATH` равен `/var/lib/grafana/problem-desk`; разместите этот каталог на постоянном хранилище, защитите его и включите в процедуры резервного копирования и восстановления.

Опрос начинается при первом посещении приложения аутентифицированным пользователем после запуска процесса плагина и продолжается до освобождения экземпляра. Источник - активные firing-оповещения Grafana Alertmanager API, не pending-оповещения. События, пропущенные во время простоя, восстановить нельзя; загрузки истории нет. Эпизод считается восстановленным только если он отсутствует в успешном полном снимке источника, но не при сетевой ошибке.

Настройка загрузки неподписанного плагина описана в разделе [установки](INSTALL.md), меры защиты - в разделе [безопасности](SECURITY.md).
