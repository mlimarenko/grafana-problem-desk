# Безопасность и эксплуатация

**Problem Desk - общее рабочее пространство организации, а не граница доступа по папкам.** Он не воспроизводит ACL Grafana Alerting на уровне папок. Данные оповещений, видимые настроенной сервисной учетной записи, через плагин доступны участникам организации. Администратор не должен включать приложение там, где это раскроет данные с ограниченным доступом.

Viewer может читать; Editor и Admin могут комментировать, подтверждать и отменять подтверждение и продвигать настроенные процессы; Admin может настраивать приложение, редактировать политику организации и запускать ручную синхронизацию. Backend определяет автора по доверенному пользователю Grafana SDK, а не по данным запроса. Настройте сервисную учетную запись в пределах организации с правом чтения оповещений; backend сверяет ее организацию с доверенным ID организации плагина.

Политика организации проверяется на сервере и хранится неизменяемыми ревизиями с журналом только на добавление. Писать ее может только Admin; она никогда не выдает права записи Viewer и не меняет авторизацию Grafana, не содержит учетных данных и не исполняет скрипты, регулярные выражения, webhooks или правила уведомлений. Метаданные процессов и уровней никогда не переписывают исходное состояние источника `active`/`recovered`.

Список ответственных - отдельный снимок участников организации, который Admin
явно публикует из каталога Grafana. Его читают Editor и Admin, но не Viewer.
Публикуются только UID, логин и имя, без почты и прав. Обновление не расширяет
права токена источника. Новое назначение проверяется по текущему списку в той же
транзакции; прежние метки ответственного не выдают прав и не стираются при обновлении.

Комментарии и подтверждения хранятся в постоянной базе SQLite отдельно от базы Grafana с разделением по организациям. Считайте хранилище и резервные копии конфиденциальными: комментарии и контекст оповещений могут содержать служебные сведения. Ограничьте доступ, защитите копии и установите подходящие сроки хранения. Токен сервисной учетной записи храните в защищенной конфигурации плагина.

Подтверждение не заглушает и не разрешает оповещение. Плагин не подписан; разрешайте его загрузку только по точному ID для разработки на собственном сервере.

Как сообщить об уязвимости, описано в [политике безопасности](../../SECURITY.md).
